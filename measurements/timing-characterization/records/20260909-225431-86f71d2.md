# Record 20260909-225431-86f71d2

- **Record ID**: 20260909-225431-86f71d2
- **Claim**: the first characterized (as opposed to inherited or estimated)
  timing data for the `logic_tile` block, per `spec/framework-gaps.md` item
  **G4 — Timing characterization (no inherited numbers)**. One fixed piece
  of routed geometry (`layout/logic_tile.def`) re-timed in a fresh OpenSTA
  session at each of the 18 `sky130_fd_sc_hd` liberty corners the sky130A
  PDK ships, twice per corner: once with LEF-only (unannotated) parasitics
  and once with parasitics extracted from `layout/logic_tile.gds` and
  annotated in as SPEF. Regenerate with `./flow/sta-sweep.sh`.
- **What this supersedes**: nothing — this is the first record under
  `measurements/`. It does **not** supersede
  `layout/logic_tile.par.json`'s own `corners[]` array; that array is
  `klt place-and-route`'s in-flow, pre-signoff estimate from
  `estimate_parasitics -global_routing` (a Steiner-topology Elmore
  estimate), which `layout/README.md` already disclaims as "not a published
  performance number". The two are cross-checked against each other below.
- **What this does *not* do**: it publishes no number into
  `spec/tile-spec.md`. That spec's timing rows still read "No numbers in
  this spec" and changing them is a ratified spec change requiring its own
  decision record — this record is the evidence such a decision record
  would cite, not the ruling.

## Method

`./flow/sta-sweep.sh --update`, in one invocation:

1. **Rewrote the routed DEF's escaped identifiers twice**
   (`flow/sta_sanitize_names.py`) — an un-escaped copy, and a copy whose
   names carry no `/` or `.`. Both rewrites are connectivity-preserving and
   name-only; see "Friction" below for why each is needed.
2. **Extracted first-order lumped-RC parasitics once** from the committed
   `layout/logic_tile.gds`:

   ```
   klt extract layout/logic_tile.gds --deck sky130 \
     --parasitics --spef <out>.spef \
     --def-net-names --def-net-connections <un-escaped DEF> \
     --def-pins layout/logic_tile.def \
     --abstract-cells 'sky130_fd_sc_hd__*'
   ```

   `status: extracted`, 152 nets, 94 top-level pins, 0 devices (every
   standard cell abstracted to a pin-only black box — 11 distinct masters —
   so only the interconnect's parasitics are extracted; the cells' own
   delays come from the liberty deck).

   `klt extract`'s own `parasitics` summary, verbatim:

   | Field | Value |
   | --- | --- |
   | `r_count` | 152 |
   | `c_count` | 152 |
   | `cc_count` (coupling caps) | 1566 |
   | `l_count` | 0 |
   | `total_resistance_ohm` | 73552.4629 |
   | `total_capacitance_ff` | 414.649277 |
   | `total_coupling_capacitance_ff` | 9.758286 |
   | `distributed_rc` | `false` |

   `klt extract`'s own `parasitics.model` statement — what this RC model
   does and does not account for — verbatim:

   > **capacitance**: "net-to-ground for every net's own (non-coupled)
   > area/perimeter, plus net-to-net for the vertical-overlap coupling
   > `coupling` describes below -- a coupled net pair gets a direct
   > capacitor between their two hub nodes, not just capacitors to the
   > deck's ground/substrate net"
   >
   > **coupling**: "vertical overlap (crossover) unconditionally -- where
   > one net's conductor on an adjacent metal level sits directly over
   > another *distinct* net's conductor, that overlap area is charged
   > between the two nets instead of to ground (issue #760) -- plus lateral
   > (same-layer, sidewall) coupling, but only for a net pair naming one of
   > the caller's declared `--critical-net` nets (issue #976): facing-edge
   > length within that layer's own minimum-spacing lookback is charged
   > between the two nets, *additively* (not deducted from either net's
   > substrate fringe term, unlike the vertical case -- a known
   > simplification). Any same-layer pair with neither side named
   > `--critical-net`, and fringe shielding in general, are still not
   > modelled"
   >
   > **resistance**: "single lumped series resistance per net, distributed
   > as a star across that net's device terminals (issue #592) -- not a
   > per-segment, distributed RC ladder, *unless* `--distributed-rc` names
   > this net via `--critical-net` (issue #977, Epic #709 Phase 2b) [...]"
   >
   > **frequency**: "quasi-static -- one frequency-independent R and C per
   > net; no skin effect, no distributed transmission-line behavior"

   No `--critical-net` and no `--distributed-rc` were used, so every net in
   this sweep is the single-hub star model above.
3. **Ran `klt sta` three times per corner** — LEF-only on the committed
   DEF, LEF-only on the name-rewritten DEF (the timing-neutrality control),
   and SPEF-annotated on the name-rewritten DEF — with
   `constraints.clock_port = clk`, `clock_period_ns = 20`. The DEF is
   byte-identical across every run in the sweep; only `pdk.corner` (and the
   presence of the SPEF) varies.

### Corner set: 18, and why

The sky130A PDK ships 18 `sky130_fd_sc_hd__*.lib` files: 16 distinct PVT
points plus `ff_n40C_1v95_ccsnoise` and `ss_n40C_1v60_ccsnoise` (the same
two PVT points with CCS noise models added). All 18 were run — the 16 that
`layout/logic_tile.par.json`'s in-flow sweep already names were the stated
floor, and running the full liberty listing rather than a hand-picked
subset matches the 18-corner matrix the sibling digital canary
`sky130-modexp` ratified. `flow/sta-sweep.sh` asserts its corner list
against the PDK's own liberty directory listing on every run, so a PDK
revision that adds or drops a corner fails the sweep rather than silently
narrowing it. As expected, each `_ccsnoise` corner reproduces its base
corner's numbers exactly (OpenSTA's delay calculation here does not consume
the CCS noise model), which is itself a useful consistency check on the
sweep.

### Timing-neutrality control

`flow/sta-sweep.sh` runs an unannotated analysis on the committed DEF *and*
on the name-rewritten DEF at **every** corner and refuses to record the
corner's SPEF run unless `worst_slack_ns`, `total_negative_slack_ns`,
`fmax_mhz`, `setup_violation_count`, `hold_violation_count`,
`clock_skew_ns` and `estimated_power_mw` are all identical between them.
All 18 corners passed. The name rewrite therefore moved no timing or power
number in this run — the SPEF-annotated results below are an analysis of
the committed geometry, not of something else.

### SPEF annotation

Every SPEF run reported `spef_annotation.annotation_complete: true`, with
`design_nets_annotated: 139` of `design_nets_total: 139` and an empty
`design_nets_missing_sample`. SPEF-side, 139 of the SPEF's 152 declared
nets exist in the linked design; the 13 that do not are the flat
extraction's intra-standard-cell `$N` nodes, which a gate-level design
never has (documented, expected — see `docs/cli/sta.md`'s own note that
this ratio is expected to sit below 1 even on a perfectly-correlated run).
**No run in this record is marked non-measurement**; had any corner
reported `annotation_complete: false`, `flow/sta-sweep.sh` would have
exited non-zero rather than record it.

### Binding corners

- **Setup — binding corner is `ss_n40C_1v28`** (slow-slow process, −40 °C,
  1.28 V): SPEF-annotated WNS 15.1760 ns against the 20 ns SDC period —
  i.e. 4.824 ns of worst-case data-path delay *plus* library setup time —
  extrapolated `fmax_mhz` **207.29 MHz** (see the Fmax caveat below). The
  **LEF-only-vs-SPEF delta at this binding corner is −0.2890 ns of setup
  slack** (15.4650 → 15.1760), which is 6.0 % of that 4.824 ns
  path-plus-setup budget — the largest interconnect penalty of any corner,
  as expected:
  the same RC network costs proportionally more where the cells drive
  weakest. Fmax at the binding corner drops 220.50 → 207.29 MHz (−6.0 %)
  when real parasitics are annotated.
- **Hold — no binding corner can be ranked, and none is needed here.**
  `hold_violation_count` is **0 at every one of the 18 corners in both the
  LEF-only and the SPEF-annotated run**, so no corner binds. It cannot be
  ranked more finely than that because `klt sta` reports a hold-side
  *violation count* but no hold-side WNS/TNS metric (it runs
  `report_worst_slack_metric -setup`/`report_tns_metric -setup` only) —
  filed upstream, see "Friction" below. The structurally binding corner for
  hold is the fastest one, `ff_n40C_1v95`; it reports 0 hold violations
  with parasitics annotated, and the LEF-only-vs-SPEF delta in
  hold-violation count there is 0 → 0. For reference,
  `layout/logic_tile.par.json`'s in-flow estimate puts the worst hold slack
  at that same corner at +0.34889 ns.

### Cross-check against the in-flow estimate

`layout/logic_tile.par.json`'s own `route`-stage numbers come from the same
place-and-route run that produced the analysed DEF, using OpenROAD's
`estimate_parasitics -global_routing`. At `tt_025C_1v80` it reports
`worst_slack_ns` 19.342 / `fmax_mhz` 1519.79 / `estimated_power_mw` 0.0312;
this record's SPEF-annotated run reports 19.3486 / 1535.12 / 0.0311. The
two agree to within 0.007 ns of slack, 1.0 % of Fmax and 0.3 % of power —
two independently-derived parasitic models landing in the same place, which
is the sanity check that makes the extracted-SPEF path credible. Note the
in-flow estimate is *slightly pessimistic* here relative to the extracted
lumped-RC model. At the binding slow corner the in-flow estimate gives
`setup_slack_ns` 15.0984 vs. this record's 15.1760 — again within 0.08 ns.
Neither of those in-flow numbers is published as a measurement; they are
cited only as an independent cross-check.

## What these numbers do not claim

- **Ideal clock.** `klt sta` times an SDC-only, non-propagated clock even
  though the analysed DEF contains a real clock tree (three clock-net
  buffers). `clock_skew_ns` reads 0 at every corner for that reason — it is
  not a claim that this tile has zero skew. Propagated-clock STA is listed
  as tool follow-up work in `docs/cli/sta.md` and is deliberately not
  hand-rolled here.
- **Extrapolated, not bisected, Fmax.** `fmax_mhz` is
  `report_fmax_metric`'s `1/(T−WNS)` extrapolation from a single 20 ns
  analysis, not a bisection search that re-times the design at successively
  shorter periods. With ~15–19.6 ns of slack against a 20 ns period, that
  extrapolation is far outside the range the single analysis actually
  measured, and the cell-delay non-linearity it ignores means the true
  closing frequency will be lower. **The trustworthy numbers in this record
  are the slacks and the data-path delays; the Fmax column is a derived
  convenience, and the tile's real Fmax is an open question this record
  does not settle.**
- **First-order lumped RC only** — one series R and one ground C per net in
  a star topology, no distributed RC ladder, no field solve, quasi-static.
  See the `parasitics.model` block quoted above for the exact scope.
- **No power delivery network.** The tile carries only the `met1` row rail
  klt's routing-obstruction fallback draws (klayout-tools#1442); there are
  no straps, no tapcells and no IR-drop analysis. Power-supply-induced
  timing variation is therefore not modelled at all.
- **Tile only, no switch matrix and no inter-tile routing.** Only the BEL
  logic exists to characterize today (`spec/framework-gaps.md` G1/G2 for
  the switch matrix have not landed), so nothing here characterizes fabric
  routing delay.
- **`estimated_power_mw` is an OpenSTA estimate against a default switching
  activity**, not a measured or vector-driven power number.

## Friction (per `CLAUDE.md`'s friction protocol)

Building this record hit four klayout-tools gaps. All four are filed
generically against `2AMLogic/klayout-tools`; gaps 1, 2 and 4 are worked
around in-repo by `flow/sta_sanitize_names.py`, gap 3 is not worked around
at all.

1. **`klt extract --def-net-connections` does not un-escape the DEF's own
   identifiers before matching them** — filed as
   [`2AMLogic/klayout-tools#1623`](https://github.com/2AMLogic/klayout-tools/issues/1623).
   A routed DEF spells a Verilog escaped identifier with its backslashes
   intact (`g_slice\[0\].u_slice/_08_`), while `--def-net-names` recovers
   the same net from the layout as `g_slice[0].u_slice/_08_`. The two never
   compare equal, so **every** hierarchical net silently gets no `*CONN`
   block — a `*D_NET` whose RC network has no pin node at all and therefore
   contributes nothing to any delay. Same family as the LVS-side gap
   already filed as klayout-tools#1371. Measured here: 40 of 152 `*D_NET`
   blocks — including every net on the critical path — were emitted with no
   `*CONN` until the DEF was un-escaped first.
2. **`klt sta` reports `annotation_complete: true` for a SPEF that
   annotates nothing the delay calculator can use** — filed as
   [`2AMLogic/klayout-tools#1624`](https://github.com/2AMLogic/klayout-tools/issues/1624).
   With gap 1 in play, the correlation probe (which uses `get_nets`)
   resolved all 139 design nets and reported `annotation_complete: true`,
   `design_nets_missing_sample: []` — while `report_checks` produced
   **bit-identical path delays to 6 decimal places** with and without the
   SPEF at every corner tried, because OpenSTA's SPEF reader silently
   dropped every `*D_NET` (`net ... not found` / `instance ... not found`
   for any flat name containing the `/` divider, and `*D_NET` blocks with
   no pin node at all). `estimated_power_mw` *did* move, which makes the
   failure look even more like a real annotation. This is precisely the
   "incomplete annotation masquerading as a measurement" that
   `spef_annotation` exists to prevent, reached from a direction the check
   does not cover.
   **This record's own defence against it** is the timing-neutrality
   control plus the fact that its SPEF-annotated numbers *do* differ from
   the LEF-only ones at every corner (the `Δ` column above), in the
   direction and with the corner-ordering physics predicts.
3. **`klt sta` reports no hold-side WNS/TNS** — filed as
   [`2AMLogic/klayout-tools#1625`](https://github.com/2AMLogic/klayout-tools/issues/1625).
   The response carries `hold_violation_count` but only setup-side
   `worst_slack_ns`/`total_negative_slack_ns`, so a hold-clean design's
   corners cannot be ranked by hold margin and "the binding corner for
   hold" is unanswerable from the report alone (see "Binding corners"
   above).
4. **`klt extract --spef` stamps a wall-clock `*DATE` into the SPEF
   header** — filed as
   [`2AMLogic/klayout-tools#1627`](https://github.com/2AMLogic/klayout-tools/issues/1627).
   Two runs of the identical extraction against the identical GDS produce
   SPEFs differing in exactly that one line and nothing else (verified by
   diff), which makes the `spef_sha256` provenance recorded in every
   per-corner report non-reproducible and would fail
   `flow/sta-sweep.sh`'s check mode on every run for no design reason. Same
   class of gap as klayout-tools#1367 (the DEF→GDS merge's per-structure
   timestamps, which `flow/gds_canonicalize.py` already zeroes);
   `flow/sta_sanitize_names.py`'s `spef-sanitize` mode rewrites the `*DATE`
   line to a constant.

A fifth piece of friction is not a `klt sta`/`klt extract` gap and is
recorded here only because it changed the committed layout in the same
commit: klt 0.3.0's row-rail routing-obstruction fix (klayout-tools#1442)
inserts physical-only `sky130_fd_sc_hd__fill_*` cells that
`flow/lvs.sh`'s `--abstract-cells 'sky130_fd_sc_hd__*'` pattern turned into
unmatched circuits, failing LVS. The fix is the `[!f]*` pattern
`docs/cli/lvs.md`'s own worked sequence already prescribes for exactly this
reason; `flow/lvs.sh` now uses it and LVS is `match` again.

## Reproducing

```
./flow/layout.sh      # verify the committed GDS/DEF/report regenerate byte-identically
./flow/sta-sweep.sh   # re-extract parasitics, re-sweep all 18 corners, diff every report
```

Both exit 0 only if nothing has drifted. Requires `klt`, `openroad`, a
native `yosys` (for `flow/layout.sh` only), and a resolvable sky130A PDK.

**Toolchain note.** The committed `layout/` artifacts were regenerated in
this same commit, because the toolchain that produced the previous ones
(klt 0.2.x) no longer exists in this environment and the newer klt 0.3.0
legitimately produces a different layout (the row-rail fix above). A
standalone `klt sta` needs the routed **DEF**, which was never committed
before, and a DEF is only honest evidence when it comes from the same
place-and-route run as the GDS the parasitics are extracted from — so
`layout/logic_tile.{gds,def,par.json,lvs.json,drc.json}` were all
refreshed together, exactly as `flow/README.md`'s `flow/lvs.sh` section
already prescribes for a layout change. DRC remains `clean`, LVS remains
`match`.

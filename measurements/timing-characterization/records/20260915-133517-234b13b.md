# Record 20260915-133517-234b13b

- **Record ID**: 20260915-133517-234b13b
- **Claim**: T1 checklist item 7 (Epic #4, issue #29) -- post-layout,
  PEX-based re-verification with a real SDF back-annotation. Regenerates a
  fresh `klt place-and-route` run of the same synthesized `logic_tile`
  netlist PR #22 characterized, opting in to `post_route_spef` +
  `post_route_sdf` (klayout-tools issue #1002), and confirms the regenerated
  DEF is **byte-identical** to the already-committed, already-characterized
  `layout/logic_tile.def` -- so the SDF this run writes describes the exact
  geometry PR #22's 18-corner sweep already measured, not a different run.
  `sim/tb_logic_tile.v` then runs gate-level against the as-built
  `sky130_fd_sc_hd` netlist from that same run, twice: zero delay, and with
  the real SDF back-annotated via Icarus's `$sdf_annotate`. Regenerate with
  `./flow/sdf-resim.sh`.
- **What this supersedes**: nothing -- first record under this experiment.
  Does not supersede
  `measurements/timing-characterization/records/20260909-225431-86f71d2.md`
  (the 18-corner STA sweep); this record's own `spef_sta.worst_slack_ns`
  (19.3946 ns at `tt_025C_1v80`) is a fresh, independent re-derivation of a
  very close number to that record's own `tt_025C_1v80` SPEF-annotated
  cross-check (19.3486 ns) -- the small delta is klt 0.4.0 vs. the 0.3.0
  that produced that record (see `flow/README.md`'s "Known drift, issue
  #23"), not a design change; both runs analyse the identical geometry.
- **What this does *not* do**: it does not achieve an SDF-**annotated**
  pass/fail result -- that leg is blocked by a real, cited, upstream tool
  defect (see "Result 2" below), not achieved and not faked.

## Method

`./flow/sdf-resim.sh --update`, in one invocation:

1. Re-ran `klt synthesize` + `klt place-and-route` with the identical
   request `flow/layout.sh` uses (same RTL, same floorplan, same seed),
   adding `"post_route_spef": true, "post_route_sdf": true`. `stage_reached:
   "route"`.
2. Diffed the regenerated DEF against the committed `layout/logic_tile.def`
   -- **byte-identical** (`diff -q`, no canonicalization needed; the DEF is
   already byte-reproducible across runs of the identical, seeded request,
   per `flow/layout.sh`'s own header note).
3. `spef_sta` from that run's response:
   ```json
   {
     "spef_path": ".../logic_tile_route.spef",
     "sdf_path": ".../logic_tile_route.sdf",
     "worst_slack_ns": 19.3946,
     "total_negative_slack_ns": 0,
     "setup_violation_count": 0,
     "hold_violation_count": 0,
     "nets_annotated": 139,
     "nets_total": 286,
     "design_nets_annotated": 139,
     "design_nets_total": 139,
     "annotation_complete": true,
     "annotation_warning": null
   }
   ```
   `annotation_complete: true` (139/139 design nets), matching PR #22's own
   `klt sta` annotation-completeness bar -- this SDF was written from a
   real-parasitics session, not an `estimate_parasitics -global_routing`
   estimate.
4. Canonicalized the SDF (`flow/sdf_canonicalize.py`, strips the volatile
   `(DATE ...)` header line the same way `flow/sta_sanitize_names.py`
   already does for the SPEF header) and committed it as
   `measurements/timing-characterization/logic_tile_route.sdf` (823 lines;
   215 `IOPATH` entries across 44 standard-cell instances, 179
   `INTERCONNECT` entries for the top design).
5. Compiled and ran `sim/tb_logic_tile.v` **unmodified**, gate-level,
   against the as-built netlist from step 1 plus the sky130A PDK's
   `sky130_fd_sc_hd` behavioral Verilog cell models (`primitives.v` +
   `sky130_fd_sc_hd.v`, neither `FUNCTIONAL` nor `USE_POWER_PINS` defined --
   the branch carrying `specify` blocks), via Icarus Verilog 13.0
   (`-gspecify -ginterconnect -T typ`, no SDF yet).
6. Generated the extra `$sdf_annotate`-carrying elaboration root
   (`flow/sdf_annotate_shim.py`, mirroring `klt functional-verification`'s
   own `_write_sdf_annotate_shim` idiom) and re-compiled + re-ran the same
   testbench with `$sdf_annotate` pointed at the committed SDF from step 4.

## Result 1: zero-delay gate-level -- PASS

```
PASS: tb_logic_tile -- 4 checks, 0 failures
```

The tile's functional behavior (independent per-slice LUT config, per-slice
clock-enable, shared reset -- the same three properties
`sim/README.md` already documents for the RTL-level run) survives synthesis
and place-and-route onto real `sky130_fd_sc_hd` standard cells, checked
against the exact as-built netlist PR #22's timing numbers describe. This is
a zero-delay check -- it says nothing about timing, only that the mapped
gates are still functionally correct.

## Result 2: SDF-annotated gate-level -- BLOCKED (upstream tool defect, filed and cited, not faked)

```
ERROR: NULL handle passed to vpi_scan.
vvp: vpi_iter.cc:71: __vpiHandle* vpi_scan(vpiHandle): Assertion `0' failed.
Aborted (core dumped)
```

`vvp` crashes outright (SIGABRT) applying the real SDF from Result 1's own
run. Bisected down to a minimal, generic (non-sky130, non-tile-specific)
15-line reproduction: **any** `INTERCONNECT` entry naming an escaped
Verilog identifier containing a literal `.` or `[`/`]` crashes `$sdf_annotate`
this way -- independent of file size (reproduces with exactly 1 entry),
independent of which of those two characters is present, and confirmed
identically through `klt functional-verification`'s own `options.sdf` CLI
path against a real synthesized-and-routed design, not just this repo's
hand-wired `$sdf_annotate` shim. Filed generically (no design-specific
detail) as
[klayout-tools#1890](https://github.com/2AMLogic/klayout-tools/issues/1890).

This design's `generate`-block RTL (`design/rtl/logic_tile.v`'s
`g_slice[N].u_slice`) is exactly the shape that triggers it once flattened
by synthesis/place-and-route -- so this is not a design defect or a
misapplied recipe, it is the documented SDF back-annotation capability
(`klt place-and-route --post_route_sdf` + `klt functional-verification
--options.sdf`, or the equivalent hand-wired Icarus mechanism this script
uses) being currently unusable on this class of design. `./flow/
sdf-resim.sh` re-attempts this leg on every run and **expects** to
reproduce this exact crash signature -- a clean pass, a different failure,
or no crash at all would mean klayout-tools#1890's status changed, and is
treated as a script failure (not a silent "still broken") so this record
does not go stale unnoticed.

## `sim/tb_lut4_slice.v`: not attempted, and why

`lut4_slice` has no independently placed-and-routed layout of its own --
only as a `g_slice[N].u_slice` sub-instance flattened inside the routed
`logic_tile` (`design/README.md`). Its interconnect/IOPATH delays in the SDF
above are hierarchical-path-relative to the whole `logic_tile` instance, not
to a standalone `lut4_slice` root, so `tb_lut4_slice.v`'s own top-level
`lut4_slice` instantiation cannot be SDF-annotated (nor, independent of the
klayout-tools#1890 blocker, meaningfully zero-delay gate-level checked
against *characterized* geometry) without producing a new, independently
placed-and-routed sub-block layout -- a new physical-design artifact, out of
this issue's scope. See `spec/framework-gaps.md` G4 and `sim/README.md` for
the full accounting.

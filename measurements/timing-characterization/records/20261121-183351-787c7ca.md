## Method

`klt functional-verification` runs the same cocotb module twice through two
generated requests that differ in exactly one field: `options.sdf` (absent
vs `{file: <committed SDF>, corner: "typ"}`). Shared by both legs:

- sources `layout/logic_tile.asbuilt.v`, then `primitives.v`,
  `sky130_fd_sc_hd.v` (hash-gated above); `hdl_toplevel: logic_tile`; the
  netlist's seven ports (`ce`, `clk`, `in`, `lut_init`, `out`, `reg_sel`,
  `rst`) are driven by name from the bench, and the netlist carries no
  supply pins;
- `USE_POWER_PINS` and `FUNCTIONAL` **undefined** in both legs: the cells
  use internal supplies and keep the specify branch the `IOPATH` entries
  annotate (klt rejects `options.sdf` together with a `FUNCTIONAL` define);
- `engine: icarus`, `random_seed: 359`, `timescale 1ns/1ps`, build args
  `-gspecify -ginterconnect -Ttyp` (so even the zero-delay leg elaborates
  exactly like the annotated leg; the sky130 specify-branch models carry
  `0:0:0` placeholder path delays, so leg 1 is genuinely zero-delay);
- bench timing constants, identical in both runs: **clock period 20 ns**
  (the ratified STA row's `clk` reference period, ADR-0002/0003) and
  **settling interval 4 ns** -- the sampling window after each active edge
  and the combinational settle window. The Verilog reference's 10 ns / 1 ns
  pair is too tight for the annotated design: the worst clk-to-out path
  (three `buf_4` clock buffers 3 x 0.092 + `dfxtp_1` CLK->Q 0.293 + output
  `mux2_2` ~0.118-0.177, all typ) is ~0.6-0.75 ns, which a 1 ns sample
  straddles; 4 ns observes the settled value with > 5x margin.

Each named test initializes every input itself (independence), treats X/Z
on a checked output bit as a failure, and follows the issue's sequencing:
selective capture first resets the registers, and the mixed-state reset
test establishes and observes `0101` before asserting reset with
`ce=1111`. The input was re-verified before running:
`python3 -I flow/def_to_netlist.py --check` reproduces the committed
netlist byte for byte.

## Result 3: comparison with the #250 record (116 dropped vs 28 predicted)

Re-derived before the run, against the same committed SDF
(`sha256 6416961e...`, byte-identical to what #250 pinned):
`sim/sdf_port_interconnect/predict_fanout_rejections.py` still reports 179
`INTERCONNECT` entries = **116 bit-selected-port + 5 scalar-port + 58
instance-pin** sources, 12 affected nets (fanout > 1), **28 predicted
Icarus rejections** under the fanout model, all affected entries
`0.000:0.000:0.000`.

klt 0.9.1's `zero_delay_bus_port_source_interconnect` pass (upstream
klayout-tools#2984) **has no fanout test**: it removes every
zero-delay `INTERCONNECT` whose source is a bit-selected top-level input
port, whatever the net's fanout and destination. Measured here: **all 116**
removed, not the 28 Icarus itself would reject. The 88 fanout-1 entries
Icarus would have applied (`fanout1_bitsel` in #250) are dropped too.

- **Timing value lost: none.** All 179 interconnect delays in this SDF are
  zero, so the 88 additionally-dropped entries carried no delay to lose;
  the exemption is bounded by delay value upstream, so a nonzero entry of
  this shape would still fail the run loudly rather than be dropped.
- **Cell-arc coverage: complete.** All 215 `IOPATH` entries annotate (no
  `iopath_*` drop class); their typ range in this file is **0.028-0.315
  ns** (re-derived from the committed bytes; #250 Result 8 quotes
  "0.017-0.477 ns, typ" for the same file -- that range does not match the
  committed bytes' min/max over all 645 triple members either, and appears
  to be an error in that record's prose; its counts (179/215, all
  interconnects zero) do match). The four `out[N]`-destination entries
  #250's source-side classification counts among the instance-pin 58 are
  applied via the deferred second call, not dropped.

An interconnect-only (`entries: "interconnect"`) run was **not** recorded:
the full-SDF leg passed, so the requested population (including the 215
cell arcs) is the deliverable, and an interconnect-only result would have
excluded all 215 cell arcs while applying only zero-valued net delays.

## Result 4: the delays are observable, not a silent zero-delay pass

klt's diagnostic gate (any unexempted `SDF WARNING`/`SDF ERROR` fails the
run; this run exited 0 with only the four exempted `TIMINGCHECK not
supported.` lines) plus a scratch corroboration probe -- a temporary cocotb
module polling `out` at 10 ps granularity, not committed, same requests
otherwise -- measured when `out` first reaches its settled value:

| path | zero-delay leg | annotated leg (typ) |
|---|---|---|
| registered: posedge -> `out == 0101` | 0.01 ns (first poll; delta cycle) | **0.60 ns** |
| combinational: `in` change -> `out == 0110` | 0.01 ns | **0.53 ns** |

Both annotated transitions sit where the SDF's arc sums put them
(~0.276 ns clock insertion + 0.293 ns CLK->Q + output mux; two-level mux4
chain + output mux), so the annotation moved real delay into the run -- the
same "applied means an observed timing shift" bar #250 set.

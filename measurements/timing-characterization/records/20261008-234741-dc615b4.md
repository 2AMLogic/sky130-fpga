## Method

`./flow/sta-sweep.sh --update` (2026-10-08 23:47 UTC), then
`./flow/sta-sweep.sh` (check mode) straight after. The check-mode run
reproduced every committed artifact byte-for-byte: 36 per-corner reports,
the envelope and the SPEF. Per corner, the same three single-corner runs
as before:

1. LEF-only on the committed DEF.
2. LEF-only on the name-sanitized DEF. This is the neutrality control: the
   sweep refuses the corner unless every metric matches run 1. The
   control now also compares `worst_hold_slack_ns`,
   `total_negative_hold_slack_ns` and `timing_status`.
3. SPEF-annotated on the sanitized DEF. The sweep refuses the corner unless
   `spef_annotation.annotation_complete` is `true`.

Then **one multi-corner request**: `pdk.corners` listing all 18 corners,
the same sanitized DEF and SPEF, and the same
`constraints: {clock_port: clk, clock_period_ns: 20}`. `klt sta` re-hashes
the DEF after its corner loop and refuses to report if it changed. The
trimmed response is committed as
`measurements/timing-characterization/logic_tile.sta.json`. It is admitted
only after `flow/sta_envelope_check.py` confirms:

- its corner names are exactly the 18 ratified corners, with none missing,
  duplicated or extra;
- every corner is `timing_status: "constrained"`, with `worst_slack_ns >= 0`,
  `worst_hold_slack_ns >= 0`, zero violations and zero setup and hold TNS;
- every corner has complete SPEF annotation;
- every corner's `fmax_mhz` is consistent with a 20 ns period;
- every corner entry agrees field-for-field with that corner's run-3
  report.

### Harness changes this re-sweep needed (and why)

- **SPEF `*CONN` correlation broke under the newer `klt extract`, and the
  harness now works around it.** Since klayout-tools#2145, `klt extract`
  rewrites `.` to `_` in every extracted net name, including the SPEF's
  `*D_NET` names. `--def-net-connections` still keys its pin table by the
  DEF's dotted names, so all 40 hierarchical nets (`g_slice[N].u_slice/...`)
  lost their `*CONN` blocks (99 of 139). OpenSTA then reported
  `partially_unannotated_driver_count: 40` and `delay_changed: false`, and
  the sweep's annotation guard correctly refused every SPEF run. Filed
  generically as
  [klayout-tools#2903](https://github.com/2AMLogic/klayout-tools/issues/2903).
  The workaround is the new `def-connections` mode of
  `flow/sta_sanitize_names.py`. It changes names only: dotted NETS record
  names are spelled the way the extractor now spells them, and nothing
  else changes. With it the SPEF has 139 of 139 `*CONN` blocks and every
  SPEF run is complete (`delay_changed: true`, 0 partially unannotated
  drivers).
  - This corrects an earlier attribution. The superseded record
    attributed the same signature (`partially_unannotated_driver_count:
    40`, `annotation_complete: false`) to a newer OpenROAD image. Under
    OpenROAD `26Q3-1510` it is fully explained by the extractor change and
    disappears with the name fix. The `26Q3-2276` image named in that
    record was not re-tested here.
- **`flow/sta_report_trim.py` now drops `engine_log`.** Every response
  from klt 0.6.0 on carries it, both at the top level and per
  `corners[]` entry, and it holds a random `invocation_id` plus scratch
  log paths. The trimmer also injects `layout_gds_sha256`, the GDS the
  SPEF was extracted from (`null` on LEF-only runs). Metrics,
  `timing_status`, `spef_annotation`, decks and `provenance.input` are
  kept exactly as the tool wrote them.
- **The sanitized SPEF is committed** as
  `measurements/timing-characterization/logic_tile.spef`, so the
  envelope's `spef_sha256` is anchored to committed bytes.

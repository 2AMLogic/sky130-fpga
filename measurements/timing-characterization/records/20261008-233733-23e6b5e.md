# Record 20261008-233733-23e6b5e

- **Record ID**: 20261008-233733-23e6b5e
- **Claim**: T1 checklist item 7 (issue #72) -- re-try of the SDF-annotated
  gate-level leg after klayout-tools#1890 was closed (2026-09-16).
- **What this supersedes**:
  `measurements/timing-characterization/records/20260921-062530-e8a37ad.md`
  (append-only; that record is unchanged). The outcome is unchanged in
  kind -- the SDF-annotated leg is still **not achieved** -- but the
  *reason* is now more precisely known, so this record restates it.
- **Fix located**: klayout-tools#1890 was closed by PR #1926 (merge commit
  `54f73b603dad49da83b7b2fa045344ee7a7bb543`, 2026-09-16). It is **not** a
  fix of the Icarus crash: it adds a request-validation guard
  (`_reject_sdf_escaped_divider_interconnects`) to `klt
  functional-verification`'s `options.sdf` path that rejects an SDF whose
  `INTERCONNECT` entries contain an escaped occurrence of the file's own
  `DIVIDER`, failing loud instead of letting `vvp` abort. The PR itself
  states the crash is an Icarus upstream limitation that no generated
  shim can dodge. The first release containing it is **klt v0.6.0** (v0.5.0,
  2026-09-15, predates it; confirmed by installing both and grepping
  for the guard). The generic follow-up for the remaining capability gap is
  [klayout-tools#2897](https://github.com/2AMLogic/klayout-tools/issues/2897).
- **Toolchain** (2026-10-08, throwaway venv, host tool untouched): klt
  `0.6.0` (`pip install klayout-tools==0.6.0` into a venv outside the
  worktree), OpenROAD `26Q3-1510-g6cb3f2b704` (the host docker wrapper),
  Icarus Verilog `13.0 (stable) (v13_0)`. `flow/tool_versions.sh` is **not**
  bumped: the fix does not unblock the leg, and klt 0.6.0 does not
  reproduce the committed DEF (below), so a pin bump would invalidate the
  committed layout artifacts.

## Result 1: `flow/sdf-resim.sh` end to end -- FAILS at the DEF reproducibility gate (toolchain drift)

```
error: regenerated DEF differs from the committed layout/logic_tile.def
       this run's SDF would not describe the geometry PR #22 already characterized
```

Under klt 0.6.0 / OpenROAD 26Q3-1510 the harness refuses to proceed past
leg 1a, as designed: the regenerated DEF is not byte-identical to the
committed one and the run's `spef_sta.annotation_complete` was `False`
(the same OpenSTA-annotation regression the superseded record describes
for newer OpenROAD images). No SDF was overwritten. Two harness changes
were needed just to get that far: klt >= 0.6.0 writes stage artifacts
under `.klt/<stage>/run-<id>/` instead of `.klt/<stage>/`, so
`flow/sdf-resim.sh` gained `resolve_klt_artifact()` (falls back to the
newest `run-*` directory); and the OpenROAD docker wrapper needed
`PDK_ROOT=$HOME/.volare` exported to mount the PDK. The unmodified script
cannot run against klt >= 0.6.0.

## Result 2: zero-delay gate-level -- PASS (functional only, on a non-matching netlist)

PASS: tb_logic_tile -- 4 checks, 0 failures

Run by hand (the harness's leg-1b Icarus command, `-g2012 -gspecify

## Result 3: SDF-annotated gate-level -- BLOCKED (upstream tool defect, filed and cited, not faked)

```
ERROR: NULL handle passed to vpi_scan.
vvp: vpi_iter.cc:71: __vpiHandle* vpi_scan(vpiHandle): Assertion `0' failed.
Aborted (core dumped)  -- exit 134 (SIGABRT)
```

Reproduced by hand-running the harness's leg-2 sequence
(`flow/sdf_annotate_shim.py` + `-s klt_sdf_annotate`) twice against this
run's netlist: once with the **committed** `logic_tile_route.sdf`, once
with the SDF this klt 0.6.0 run itself wrote. Both abort with the cited
signature (exit 134). The #1890 fix lives on the `klt
functional-verification` path only; the harness's raw `$sdf_annotate`
shim (necessarily so: `sim/tb_logic_tile.v` is plain Verilog, not cocotb)
is unaffected, and routing this design's SDF through `options.sdf` would
now be rejected by the new guard rather than annotated. Net: #1890 being
closed does **not** unblock T1 item 7. The blocker is carried by
klayout-tools#2897 (generic, no design detail) and #1890 got a pointer
comment.

# Regenerated layout under pinned `klayout-tools==0.8.0`: DRC, LVS, ERC and 18-corner STA (issue #252)

**This is an observation, not a signoff.** It answers the two questions the
predecessor record
`measurements/layout-reproducibility/records/20261107-213000-9e83907.md` left
open: a re-layout under the pinned `klayout-tools==0.8.0` release **is** DRC-,
LVS- and ERC-clean and setup/hold-clean at all 18 corners, and the binding
setup corner stays `ss_n40C_1v28` with SPEF WNS moving **15.2145 → 15.0971 ns
(−117.4 ps)**. No spec row, decision record, signoff pin or committed artifact
changes here. Nothing under `layout/` or `measurements/timing-characterization/`
was regenerated or committed.

## Method

One `./flow/layout.sh` in default check mode, then **five replicated
measurement legs** against a snapshot of its output. The four downstream
harnesses (`flow/drc.sh`, `flow/lvs.sh`, `flow/erc.sh`, `flow/sta-sweep.sh`)
all hardcode `LAYOUT_DIR="$REPO_ROOT/layout"` and cannot be pointed at a GDS or
DEF outside `layout/`, so invoking them would have measured the **committed**
layout. Each leg instead replicates its harness's own `klt` request shape
against the scratch artifacts; no harness, pin or committed artifact was edited,
and no `--update` / `--update-report` was run anywhere.

Environment (every step):

```bash
uv venv .klt080 && uv pip install --python .klt080/bin/python "klayout-tools==0.8.0"
export PATH="$PWD/.klt080/bin:$PATH"          # which klt -> <worktree>/.klt080/bin/klt
export PDK_ROOT="$HOME/.volare" PDK=sky130A   # resolves RECORDED_PDK_VERSION
```

`PDK_ROOT` is load-bearing: this host's default resolution is
`open_pdks f6eeac7d…`, not the recorded revision. The venv lives inside the
worktree; no host-provisioned tool was installed, upgraded or modified.

| leg | request, and the harness line it mirrors |
|---|---|
| 1. layout | `PDK_ROOT=… ./flow/layout.sh` (no `--update`) — writes `flow/build/`, gitignored; **exit 1 expected** |
| 2. DRC | `klt drc <scratch>.gds --deck sky130 --pdk sky130A` (`flow/drc.sh:115`), trimmed with `flow/drc_report_trim.py` |
| 3. ERC | `klt erc <scratch>.gds flow/erc_supply_spec.json --top logic_tile --pdk sky130` (`flow/erc.sh:141-143`) |
| 4. LVS | `lvs_sanitize_verilog.py` + `lvs_declared_pins.py`, `klt extract … --abstract-cells 'sky130_fd_sc_hd__[!f]*' --def-net-names --pins …`, then a `klt.lvs.request/1` with `options` **unset** so the inline power-connectivity check stays on (`flow/lvs.sh:227-229,255-258,286-296`) |
| 5. STA | `flow/sta-sweep.sh` §0–§4 replicated: corner-set assertion, `sta_sanitize_names.py def-connections`/`def-sanitize`, one `klt extract --parasitics --spef`, `spef-sanitize`, then 18 × {`lef-only`, `control`, `spef`} single-corner `klt sta` plus one `pdk.corners` multi-corner request, trimmed with `sta_report_trim.py` |

All 55 `klt sta` invocations ran **locally and sequentially**, as
`flow/sta-sweep.sh` does; no parallelism was added on this shared host. Nothing
here is SPICE, so no batch-fleet submission applies. Total STA wall time ~110 s.

## Leg 2 — DRC: clean, on a stricter deck

`status: "clean"`, `violation_count: 0`, `violations: []`,
`metrics.drc__error__count: 0`. `provenance.pdk.version` is the recorded
revision and `provenance.klt_version` is `0.8.0`.

Worth stating because it strengthens the result: the klt-0.8.0 `sky130` deck is
**released** (`provenance.deck.released: true`, versus `false` for the deck that
produced the committed report) and checks a substantially larger rule set —
report `schema_version` 2 → 3, and the regenerated run adds whole rule families
the committed report never checked (`*.angle.1` and `*.ongrid.1` across every
layer, `licon1.width.1`, `mcon.width.1`, `npc.*`, `nsdm.*`, `psdm.*`, `tap.*`,
`poly.endcap.diff.1`, `met*.enclosing_adjacent.via*`). It also newly reports 33
`coverage.unmodeled_rules` (`difftap.8-11`, `hvi.*`, `m1.3ab`, `m1.5`, `via.5a`,
…) — rules the deck declares it does not model, which the committed report's
schema had no field for. So the regenerated GDS is clean against *more* rules
than the committed one was ever checked against; it is not clean merely because
less was asked of it.

The two reports are therefore **not** diff-comparable, and no diff of them is
claimed here. `provenance.pdk.compatibility.status` reads `"mismatch"` (the deck
expects `open_pdks f6eeac7d…` while `PDK_ROOT` resolves the recorded
`c6d73a35…`); the pinned revision is the one the whole evidence base uses, so
that field is a note, not a finding.

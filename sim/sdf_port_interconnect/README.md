# `sim/sdf_port_interconnect/` — why `$sdf_annotate` drops some `INTERCONNECT` entries

A hand-written, self-contained reproducer for issue #250. It needs **no**
OpenROAD, no `klt`, no place-and-route and no routed tile — just Icarus
Verilog 13.0+ and the pinned sky130A cell models.

```bash
./sim/sdf_port_interconnect/run.sh
```

It is **not** part of `./sim/run.sh`. That loop compiles RTL with
`-g2012 -Wall` and no `-gspecify`/`-ginterconnect`, so it cannot run this
fixture at all.

## The question it answers

Record
[`measurements/timing-characterization/records/20261017-sdf-sanitize-d811bcd.md`](../../measurements/timing-characterization/records/20261017-sdf-sanitize-d811bcd.md)
Result 3 observed **28 of 179** `INTERCONNECT` entries rejected by
`$sdf_annotate` (`Could not find intermodpath!` /
`Could not insert intermodpath!`), every one of them sourced from a
top-level input port bit, and recorded that "the cause of the 28 rejections
was not isolated; it is not a name problem".

## The answer

**The deciding variable is the fanout of the source net, not the source's
spelling.** Icarus Verilog 13.0's `$sdf_annotate` can create at most **one**
interconnect modpath per *bit-selected top-level port* net. On such a net
with physical fanout N it annotates exactly one destination — the one
belonging to the **last-declared** instance on that net — and rejects the
other N−1 entries. The rejection is independent of SDF entry order, of
testbench activity, and of whether the destination pin declares its own
`specify`/`IOPATH` block. Scalar top-level port nets and
instance-pin-sourced nets are unaffected at any fanout, and inserting a
buffer so the source becomes a cell output pin makes the entries annotate
cleanly.

Applied to the committed
[`logic_tile_route.sdf`](../../measurements/timing-characterization/logic_tile_route.sdf)
this predicts 8 four-way `in[N]` nets × 3 + 4 two-way `ce[N]` nets × 1 =
**28** rejections, with sinks `S0`×12, `S1`×12, `A`×4 — the record's
observed figures exactly. `run.sh` leg G asserts that prediction on every
run.

The measured behaviour diverges from the way `klayout-tools`'
`functional_verification_sdf.py` documents this failure (its "shape (b)"
notes), in three respects, so the divergence was filed upstream as
[klayout-tools#5705](https://github.com/2AMLogic/klayout-tools/issues/5705)
rather than treated as a duplicate of the closed #1619 / #2984.

Full method, verbatim simulator messages, the two open questions this
settles, and the consequence for T1 item 7:
[`measurements/timing-characterization/records/20261114-sdf-port-interconnect-564db73.md`](../../measurements/timing-characterization/records/20261114-sdf-port-interconnect-564db73.md).

## Two things not to "simplify"

1. **The DUT is a nested child named `dut`**, mirroring
   `sim/tb_logic_tile.v`'s `logic_tile dut (...)`. klayout-tools#1056 is a
   nesting fix; a flat top-level DUT tests a different question.
2. **`$sdf_annotate` rides in a second elaboration root**
   (`-s klt_sdf_annotate`) generated by `flow/sdf_annotate_shim.py`, not in
   the testbench's own `initial` block — exactly as `flow/sdf-resim.sh` leg
   2 does.

## Two deliberate differences from `flow/sdf-resim.sh`

Neither changes that script, which stays pinned by the active record (#162).

1. **The PDK is pinned exactly.** `run.sh` resolves the sky130A cell models
   to `flow/tool_versions.sh`'s `RECORDED_PDK_VERSION` and fails loud if
   that revision is not installed. `flow/sdf-resim.sh` prefers whatever
   `klt pdk find` resolves, which on at least one host is a *different*
   revision from the pinned one.
2. **Verdicts come from the transcript, never from an exit code.** `vvp`
   exits 0 after skipping an annotation it could not apply, so every
   "applied" verdict here is additionally corroborated by rescaling the
   case delay and observing the shifted edge in the waveform.

## Entry names are unescaped on purpose

The fixture uses plain instance names (`u_a0.S0`), never the real design's
`generate`-flattened escaped identifiers
(`g_slice\[0\]\.u_slice\/_09_.S0`). Escaped dividers are a separate,
already-closed question (klayout-tools#2897,
`flow/sdf_sanitize_names.py`); mixing them in would confound this
measurement, and the record being explained states the rejections are "not
a name problem".
